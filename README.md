# 😎 Чёткий Ярославль — автоматические новости ВКонтакте

**Отдельный бот** для [сообщества «Чёткий Ярославль»](https://vk.ru/club243223029). Автомобильный паблик и другие репозитории не затрагиваются.

## Что делает
- До **30 публикаций в сутки**, 24/7 по часовому поясу `Europe/Moscow` (слоты по 48 минут).
- На каждом запуске собирает RSS-новости с привязкой к **городу Ярославлю**; берёт материалы не старше 36 часов.
- ИИ генерирует **одно предложение** в стиле дружелюбного дерзкого городского парня, **три новые тематические хэштега** с привязкой к Ярославлю.
- Не повторяет URL и уже использованные хэштеги. Сравнивает заголовки по сходству; ИИ дополнительно сверяет события с опубликованными заголовками.
- История в `history.json` сохраняется между запусками; отклонённые ссылки не проверяются снова.
- Если свежих проверяемых новостей нет — **не выдумывает** публикацию. 30 — верхний предел, не гарантия.

## Подключение (без передачи ключей в чат)
В GitHub откройте [Settings → Secrets and variables → Actions](https://github.com/76kovka76-hub/chetkiy-yaroslavl-vk/settings/secrets/actions) и добавьте **Repository secrets**:

| Имя | Что хранит |
| --- | --- |
| `YAROSLAVL_VK_TOKEN` | Токен VK, разрешающий `wall.post` для **группы 243223029** |
| `YAROSLAVL_OPENAI_KEY` | API-ключ OpenAI для ИИ-редактора (API оплачивается отдельно) |

**Не используйте `VK_ACCESS_TOKEN` и `VK_GROUP_ID` от автомобильного паблика.** Здесь другие имена секретов и фиксированный ID 243223029.

Для сохранения истории GitHub Actions требуется `Settings → Actions → General → Workflow permissions → Read and write permissions`. [Прямая ссылка](https://github.com/76kovka76-hub/chetkiy-yaroslavl-vk/settings/actions).

## Тест → запуск
1. В [.github/workflows/publish.yml](.github/workflows/publish.yml) по умолчанию `DRY_RUN: "true"`. Автоматическое расписание **не публикует ничего** и **не вызывает ИИ** при тестовом режиме.
2. Добавьте оба секрета, затем откройте [Actions](https://github.com/76kovka76-hub/chetkiy-yaroslavl-vk/actions/workflows/publish.yml) → **Run workflow** для **ручного теста**. Он запишет черновик в логи и **не опубликует пост**.
3. Просмотрите лог: источник, город, главное событие, один короткий текст, три хэштега.
4. Когда источники и тексты проверены, измените `DRY_RUN: "true"` на `DRY_RUN: "false"` в [workflow](.github/workflows/publish.yml). С этого момента запуски смогут публиковать записи в VK при наличии прав и исправных источников.
5. Проверьте первые публикации в [ВК](https://vk.ru/club243223029) и обновление `history.json`.

## Источники и ограничения
RSS-источники на текущем этапе: сайт «Городской телеканал» (`https://www.gtk.tv/rss.xml`) и подборки Google News по Ярославлю. **Доступность лент из GitHub Actions ещё не подтверждена**; проверьте в тестовом запуске. Наличие названия города в заголовке не является полной проверкой фактов. Перед бесконтрольным запуском рекомендуется добавить официальные источники и отдельную проверку чувствительных тем.

**Дубли:** совпадения ссылок и повторные хэштеги блокируются жёстко, но автоматическая проверка смысла заголовков не даёт абсолютной 100% гарантии отсутствия одинаковых событий под разными заголовками. При необходимости усилим проверку после реальных тестов.

**Изображения:** не публикуются, чтобы не использовать чужие фотографии без прав на них.

**Расписание:** GitHub Actions запускается по cron примерно каждые 5 минут, но по правилам GitHub возможны задержки и пропущенные запуски; точность минуты и 30 публикаций при любых условиях не гарантированы.
